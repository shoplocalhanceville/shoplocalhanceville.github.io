# Big Dog Brief Template — Research to Build Handoff

Every piece of work in the expanded Big Dog structure starts as one brief on this form. A brief missing any required field does not enter the build queue. One brief becomes one named package. Charles Adams is the only approver of a named package before it publishes.

## Required fields

1. Title and date opened.
2. Cell requesting the work: Research and Development, Prevention and Freshness, Sourcing and Verification, Raw Code Core, Design Integration, Media Pipeline, or Integration and Automation.
3. Problem or opportunity, stated in one paragraph with the evidence that shows it is real.
4. Source evidence: the live page, record, document, or standard each fact rests on. A fact with no source is marked Unverified and is researched or held, never built on.
5. Confidence tier for each material fact: Confirmed, Likely, or Unverified, using the standing tiers in the Charles Development Standard.
6. Raw code specification: exactly what changes, written for raw HTML, CSS, and JavaScript only. No frameworks and no build pipeline.
7. Files touched: every file the package would change, with one named owner per file for the life of the package.
8. Media and rights: every image, logo, or video the package uses, its source, its right to use, and its entry in the provenance ledger. Any item whose rights cannot be verified is not used.
9. Lighthouse budget: the tested pages this package touches and the scores it must not drop. A package that drops a tested page below the standard does not merge.
10. Acceptance test: how validation will prove the package by rendering and exercising the page, never by file comparison alone.
11. Risk and rollback: what could break, and the exact step that restores the prior state.
12. Records to update in the same pass: registries, coding sheets, and troubleshooting notes this package must land with.
13. Detail and visual check: the exact object and surface this package changes, confirmed against its source under the Detail Prevention and Visual Detection Protocol, with the before and after screenshots at phone, tablet, and desktop widths that validation will capture. Names, labels, counts, and dates in the package are verified letter by letter at this step.

## Flow

Brief opened, sourcing completed, build staged, independent validation passed, records written, package presented to Charles in a batch with its evidence.
